# Heat conduction on an STK input mesh with an XTK cut

A steady 2D heat-conduction problem on a square read from an Exodus file instead of being
generated by HMR. A circular inclusion is cut into the mesh by XTK, the left edge is held at zero
temperature, both phases carry a volumetric heat source, and the inclusion surface carries a
surface heat flux. The deck demonstrates the `STK_XTK` workflow: an STK background mesh with
nodal basis functions, decomposed and enriched by XTK. The physics follows
{doc}`HeatConduction_2D <HeatConduction_2D>`, which uses an HMR mesh.

```{exa-summary} projects/EXA/thermal/diffusion/STK_XTK_HeatConduction
```

## Problem

| | |
|---|---|
| Domain | square [−0.5, 0.5]², 10 × 10 four-node quadrilaterals in `STK_XTK_HeatConduction.g` |
| Phases | 0 "solid" (outside the circle), 1 "void" (inside the circle) |
| Inclusion | circle centred at (0, 0), radius 0.31 |
| Material, phase 0 | density 1.0, heat capacity 1.0, conductivity 0.1916229656078740 |
| Material, phase 1 | density 1.0, heat capacity 1.0, conductivity 10.0 |
| Volumetric heat source | 100.0 in both phases (`Func_HeatLoad`) |
| Surface heat flux | 100.0 on `iside_b0_0_b1_1` (phase-0 side of the circle) |
| Dirichlet condition | T = 0 on `sideset_1_n_p0` (the left edge, x = −0.5), Nitsche-enforced |
| Time | static (`tTimeSteps = 0`) |

The mesh file holds one element block, `HMR_dummy`, and two side sets: `SideSet_1` on the left
edge and `SideSet_2` on the right edge. The directory also contains the Cubit file
`STK_XTK_HeatConduction.cub`.

## Setup in MORIS

**Mesh (STK).** `STKParameterList` reads
`<MORIS root>/projects/EXA/thermal/diffusion/STK_XTK_HeatConduction/STK_XTK_HeatConduction.g`
(path built from `moris::get_base_moris_dir()`). OPT selects the workflow with
`workflow` = `"STK_XTK"`. The deck also sets the logger severity to 0 in this function.

**Geometry and phases (GEN).** One `USER_DEFINED` level set, `Func_Sphere`
(φ = R − ‖x‖, analytic), whose radius R is a design variable (lower bound 0.279, initial value 0.31, upper bound 0.341;
`Design_Variable`), with the sensitivity function `Func_Sphere_Deriv`. No phase function is set,
so the default phase assignment applies. Seven `IQI_types` are declared for the OPT callbacks
([coupling C1](../../../user-guide/interlinks.md#c1-criteria-order-gen-iqi-types-acriteria-opt-callbacks)).

**Cut and enrichment (XTK).** Conformal decomposition, `basis_rank` = `"node"`, enrichment of
mesh indices 0 and 1, ghost stabilization on, `high_to_low_dbl_side_sets`, verbose level 1, and
Exodus output of the integration mesh.

**Physics (FEM).** Legacy set-name input with lower-case set names (`hmr_dummy_c_p0`,
`sideset_1_n_p0`, …;
[coupling C5](../../../user-guide/interlinks.md#c5-mesh-set-names-xtk-produces-fem-consumes)).
`DIFF_LIN_ISO` models for both phases; `SPATIALDIFF_BULK` IWGs; the interface
`dbl_iside_p0_1_p1_0` coupled by `SPATIALDIFF_INTERFACE_UNSYMMETRIC_NITSCHE` (`NITSCHE_INTERFACE`,
penalty 100.0); `SPATIALDIFF_DIRICHLET_UNSYMMETRIC_NITSCHE` (`DIRICHLET_NITSCHE`, penalty 100.0)
on the left edge; `SPATIALDIFF_NEUMANN` on the inclusion surface; `GHOST_NORMAL_FIELD` with
`GHOST_DISPL` (0.05) on `ghost_p0` and `ghost_p1`. IQIs mirror
{doc}`HeatConduction_2D <HeatConduction_2D>`: temperature, input energies, edge diffusive fluxes
and stored thermal energy, with the boundary IQIs assigned to `sideset_1_n_p0,sideset_2_n_p0`.

**Solver (SOL).** Direct solve with `Amesos_Mumps` (MUMPS builds) or `Amesos_Superludist`;
Newton with at most 20 iterations and relative residual drop 10⁻¹².

**Optimization (OPT).** `is_optimization_problem` is false; the SWEEP block is not run.

**Output (VIS).** `STK_XTK_HeatConduction.exo` with nodal `TEMP` and `HEAT` on the bulk sets of
both phases, time offset 10.0.

## What the test checks

The Catch2 case `STK_XTK_HeatConduction` calls the workflow and requires a return code of 0,
calls it a second time without checking, and compares `STK_XTK_HeatConduction.exo.e-s.0000`:

- 2 dimensions, 405 nodes, 312 elements (exact);
- node 53 at (−0.349981904029846, −0.0500085018575191), relative tolerance 10⁻⁵;
- time value 1.0, relative tolerance 10⁻⁸;
- nodal temperature 316.54272737536 at node 53, relative tolerance 10⁻⁵.

A 4-processor reference (node 83, temperature 417.433072873308) is in the source, but CMake
registers only the 1-processor run.

## Run it

```bash
ctest -R STK_XTK_HeatConduction-1-procs --output-on-failure     # in a build with MORIS_USE_EXAMPLES=ON
```

## Notes

- `IWGDiffusionBulk` (phase-0 constitutive model) is assigned to the bulk sets of both phases,
  and `IWGDiffusionVoid` adds a second bulk IWG on the phase-1 sets.
- The `.dox` file states that the block must be named `HMR_dummy` for the current MTK block
  handling, and that a refinement strategy for the STK mesh still has to be developed.
- The `.dox` file describes quadratic elements away from the interface; the deck contains no
  interpolation-order setting for the STK mesh, and the mesh file holds four-node quadrilaterals.
